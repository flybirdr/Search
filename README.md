# 搜索

把经典文本编辑器的查找替换体验搬进 VS Code：常驻侧边栏、一次搜索出全部结果、计数、标记、跨文件替换。

搜索内核用 **Rust** 编写并编译为 WebAssembly，不依赖原生二进制，Windows / macOS / Linux 共用同一份产物。

## 界面语言

跟随 VS Code 的显示语言自动切换，不需要单独设置：

- 显示语言以 `zh` 开头（`zh-cn` / `zh-tw` 等）时使用简体中文
- 其他语言一律使用英文（扩展只提供这两套文案）

覆盖范围包括活动栏标题、视图标题、命令面板、设置页说明、面板内全部文案，以及状态行、确认对话框、错误提示。切换语言后按 VS Code 的提示重载窗口即可生效。

manifest 文案放在 `package.nls.json`（英文，默认）与 `package.nls.zh-cn.json`（中文），由 `node scripts/gen-nls.mjs` 生成；运行时代码在 `src/i18n-core.ts` 的 `EN` 表里，以中文原文为键，改完运行 `node scripts/check-i18n.mjs` 校验有没有漏译或没人用的条目。

## 功能

**基础模式（默认）**

- 输入即搜：回车或点「搜索」在当前文档找全部匹配；点「全部」直接扫整个工作区，不用进高级面板
- 结果按行展示，带行号和命中高亮，点击跳转；**整行完整展示**（2000 字符以内一个字符都不省，行首不截），更长的行才开窗，宽度交给横向滚动
- 搜索词、过滤器、替换词都有历史，输入框里按 **↑ / ↓** 直接翻用过的词（最近用的在前，最多 50 条）
- 命中数超过上限（`maxMatches` 默认 20000、单文件 2000）时显示 **`20,000+ 处`**，点提示上的「统计完整数量」可以再扫一遍拿到精确总数（只计数、不列结果，201MB 日志约 0.75 秒）
- 每次搜索都会存成一条结果记录，卡片式折叠保留；卡片内每个文件的命中再单独分组、单独折叠
- 工作区搜索**边搜边出**：点下「全部」立刻出现一张「搜索中」卡片，之后每扫完一个文件就把该文件的命中插进去，不用等整场扫完；列表始终按文件路径排列（谁先扫完不影响位置）
- 面板常驻，开关不丢状态
- 结果区独立滚动，和搜索区之间有分隔条：上下拖动改高度、双击复位、聚焦后方向键微调；高度按用户记住，换工作区也沿用

**记住的东西**

| 内容 | 存哪 | 什么时候失效 |
| --- | --- | --- |
| 搜索结果记录 | `workspaceState` | 点「清空」、删单条，或换成别的工作区 |
| 查询词 / 替换词 / 模式 / 勾选 / 方向 / 过滤器 / 高级是否展开 | `workspaceState` | 换成别的工作区 |
| 输入框历史（查询词 / 过滤器 / 替换词各 50 条） | `workspaceState` | 换成别的工作区 |
| 结果区高度 | `globalState` | 双击分隔条复位 |

这三类都在 `activate` 时就读出来并直接写进首屏 HTML，所以打开面板就是上次的样子，不会先闪一下默认值。

**搜索结果记录**

| 操作 | 行为 |
| --- | --- |
| 新搜索 | 追加一张记录卡片，自动展开并收起旧记录 |
| 点击标题栏 | 折叠 / 展开该条结果，箭头同步旋转 |
| 点击文件名 | 只折叠 / 展开该文件的命中 |
| 悬停右上角 `✕` | 删除单条记录 |
| 顶部「清空」 | 清空全部记录与编辑器高亮 |

卡片头部显示查询词、命中数、时间；展开后显示作用域、搜索模式、文件数、耗时，跨文件搜索还会给出「遍历 1240 个 · 过滤后 1180 个 · 扫描 1180/1180 · 跳过 3 个二进制」这类统计。最多保留 12 条，超出后自动丢弃最旧的一条。

这些记录跟着**工作区**走：存在 `workspaceState` 里，重载窗口、退出 VS Code 再打开都还在，只有点「清空」或删掉单条记录才消失。恢复时直接嵌进面板首屏 HTML，所以不会出现「先闪一下旧结果再被清空」的跳变；点击恢复出来的行同样能跳回编辑器。为免把存储撑大，历史超过约 1.5 MB 时先丢最旧的记录，仍超就砍掉部分条目并把卡片标成「结果被截断」。

跨文件搜索对**单个文件**有独立上限（`flySearch.maxMatchesPerFile`，默认 2000），避免一个压缩后的巨型文件吃光全局额度、导致后面的文件一个都不出现。某个文件被截断时，分组标题显示 `2000 处+`，悬停会说明「只保留了前 N 条」。

结果列表是**虚拟滚动**的：无论一个文件命中 200 条还是 2000 条，DOM 里常驻的只有视口附近的约 100 行，滚动到哪渲染到哪——大结果不再卡面板，也没有「显示更多」按钮要挨个点。

### 大文件与超大文件

跨文件搜索按体积走两条通道，大文件不会再把内存顶到文件大小：

| 体积 | 通道 | 说明 |
| --- | --- | --- |
| ≤ `flySearch.streamThresholdKB`（默认 2 MB） | 整块读入 | 一次读完，路径最短 |
| > 2 MB | 分块流式 | 每块 4 MB，内存占用与文件体积无关 |
| > `flySearch.chunkAboveMB`（默认 2 MB，即 2 MB 以上都走） | 分块**并行** | 同一个文件切成多块，多线程各扫一块，内存 = 线程数 × 块 |
| 超过 `flySearch.maxFileSizeKB`（默认 500 MB） | 跳过并点名 | 卡片写明文件名与体积，并提示如何调大 |

流式读取的几个细节：

- 每块只在**换行处**切分，块首块尾的 `^` / `$` 与整文件搜索语义一致；块尾至少保留 256 KB 重叠区，跨块的多行匹配（如 `a\nb`）也能命中。
- 编码在首块探测：UTF-8 / UTF-16（带 BOM）/ GBK。多字节字符被切在块边界上不会变成乱码，列号按 UTF-16 计算，与 VS Code 的 `Range` 对齐。
- 几百 MB 的日志、几百万行的文件也能搜；进度条实时显示「文件名 · 已读 MB · 已命中数」，随时可取消。
- 结果卡片会写「流式读取 N 个文件（共 X MB）」，便于确认大文件确实被读到，而不是被跳过。

超过 2 MB 的文件再走一层**并行分块**：块边界一律对齐到行首，切块后由线程池里的多个 worker 各读一段、各扫一段，吞吐随核数上升。块大小按「成本最优（随文件大小按 √S 增长）/ 每 worker 至少 4 块 / 单 worker 内存预算 / 1 MB 下限」取小；**是否值得拆由一个逐文件的时间预算估算决定**——拆开省不下 4 ms 就老实串行（2~3 MB 这一档通常拆了反而更慢），一般 4 MB 起才划算。一次派多少活也按字节预算算（待办字节量 ÷ 4W，夹 8MB 上限），密集期一批几百个小文件、尾声自动收缩到一次一个。单行内的模式不需要重叠，可能跨行的模式给 64 KB 重叠。完整性（行号、列号、命中数）与串行搜索逐条一致，失败时（非 UTF-8、二进制、单行过长）自动退回串行。设计细节见仓库里的 `docs/HUGE-FILE-PARALLEL.md`（并行与分块方案：策略对比、块大小公式、边界处理、瓶颈实测）。
- 单行超长（压缩成一行的 JSON、minified JS）同样能搜，缓冲区不会无界增长。
- 唯一的限制：单个匹配本身超过 256 KB、且正好跨过分块边界时可能漏报。普通文本与日志不受影响。

被体积门槛挡掉的文件不会静默消失：卡片正文会写「跳过 3 个超过 500 MB 的文件：a.log（1.2 GB）、b.log（880 MB）等，可在设置 flySearch.maxFileSizeKB 中调大」，输出日志里也会逐个记录实际体积。

### 文件枚举与过滤器

文件列表由扩展自己递归读取目录得到，不把过滤器交给任何外部 glob 解析。原因很直接：那条路一旦解析出偏差，表现就是「文件莫名只搜到一个」而且没有任何提示。自己走目录虽然多几次 IO，但每一步都可预期、可统计。

- 默认跳过 `node_modules`、`.git`、`dist`、`out`、`build`、`target`、`.next`、`coverage`、`__pycache__` 等目录
- 文件清单**每次搜索实时遍历文件系统**（Node fs 直读，无缓存、无数量上限），结果按路径排序保证确定性——同样的关键词两次搜索结果完全一致；扩展宿主不常驻清单内存
- **目录优先级**（0.1.118）：点击结果条目会给该文件所在目录及各级父目录累积「热度」；后续搜索时热目录的子树**优先遍历、优先扫描**，结果分组也按热度靠前展示（同热度内按路径序）。计数持久化在工作区存储文件里，上限 1000 个目录，超出淘汰最冷的
- 默认按扩展名跳过非文本文件：`.so`、`.a`、`.o`、`.dll`、`.exe`、`.lsdump`（AOSP ABI dump）、`.jar`、`.zip`、`.img`、`.png/.jpg`、字体、音视频、`.pdf`、`.wasm` 等约 70 种——不占搜索时间也不占结果名额
- 默认按扩展名跳过非文本文件：`.so`、`.a`、`.o`、`.dll`、`.exe`、`.lsdump`（AOSP ABI dump）、`.jar`、`.zip`、`.img`、`.png/.jpg`、字体、音视频、`.pdf`、`.wasm` 等约 70 种——不占搜索时间也不占结果名额
- 过滤器写 `*.ts` 等价于递归匹配所有 `.ts`，不需要写成 `**/*.ts`
- 多个模式用逗号分隔，支持 `**`、`*`、`?`、`{ts,js}`
- 想搜默认跳过的目录，直接把它写进过滤器即可（例如 `dist/**/*.js`），默认排除会自动让路
- 每次搜索的诊断细节会打到输出面板，命令面板搜「查看搜索日志」可直接打开
- 面板右上角带版本号（如 `v0.1.7`），可据此确认 VS Code 当前加载的是哪一版
- 结果卡片标题直接写「N 处 · M 文件」，正文固定给出「遍历 X 个 · 扫描 X/Y」，一旦只剩一个文件能立刻看出是「没枚举到」还是「枚举到了但没命中」
- 命令面板搜「自检」可一键输出：工作区根目录、当前过滤器、枚举来源、遍历/保留数量与前 50 个文件的路径

**高级模式（点「高级」展开）**

| 能力 | 说明 |
| --- | --- |
| 搜索模式 | 普通（字面量）/ 扩展（`\n \t \r \0 \xHH \uHHHH`）/ 正则 |
| 选项 | 全字匹配、区分大小写、循环查找、在选区内查找、`. 匹配换行` |
| 单文档操作 | 查找上一个 / 下一个、计数、本文档全部、标记全部、清除标记、替换、全部替换 |
| 多文档操作 | 「已打开全部」与「全部」同义，直接搜工作区里所有文件（按过滤器） |
| 跨文件 | 按过滤器搜索工作区，结果按文件分组；支持在文件中替换 |

替换串支持 `$1`、`${name}`、`\1`、`$0` 与 `\n \t`。

## 设置

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| `flySearch.defaultMode` | `normal` | 默认搜索模式 |
| `flySearch.wrapAround` | `true` | 到末尾后循环 |
| `flySearch.searchInSelection` | `false` | 默认只在选区内搜索 |
| `flySearch.highlightAllMatches` | `true` | 搜索后高亮全部匹配 |
| `flySearch.maxMatches` | `20000` | 单次搜索的全局匹配上限 |
| `flySearch.maxMatchesPerFile` | `2000` | 跨文件搜索时单文件保留的匹配上限 |
| `flySearch.maxFileSizeKB` | `512000` | 跨文件搜索的文件大小上限（500 MB） |
| `flySearch.streamThresholdKB` | `2048` | 超过这个大小改用流式分块搜索（2 MB） |
| `flySearch.chunkAboveMB` | `2` | 超过这个大小才**考虑**分块并行；是否真拆由收益估算逐文件决定（0 = 关闭） |
| `flySearch.chunkMemoryMB` | `32` | 每个 worker 的分块缓冲上限（MB） |
| `flySearch.chunkCrowdMB` | `2` | 池子还剩大量字节要扫时，超过这个大小才仍并行分块（0 = 关闭闸门，32 = 保守） |
| `flySearch.diskType` | `auto` | 磁盘介质：auto 探测（机械盘自动关分块）、ssd 强制开、hdd 强制关 |
| `flySearch.backtrackLimit` | `1000000` | 正则回溯步数上限 |
| `flySearch.includeGlob` | `**/*` | 跨文件搜索的默认过滤器 |
| `flySearch.excludeGlob` | `**/{node_modules,.git,...}/**` | 排除目录 |
| `flySearch.takeOverFindShortcut` | `false` | 用 `Ctrl+F`/`Ctrl+H` 打开本面板 |

## 正则语义差异

普通模式和扩展模式与经典编辑器语义完全一致。正则模式由 `fancy-regex` 驱动（Rust），与 Boost/PCRE 系实现的差异如下：

| 语义点 | Boost/PCRE 系 | 本扩展 |
| --- | --- | --- |
| `\K` | 支持 | 不支持，明确报错并给出改写建议 |
| `\G`、递归 `(?R)`、条件组 `(?(1)...)` | 支持 | 不支持，明确报错 |
| 占有量词 `a++`、原子组 `(?>...)` | 支持 | 不支持，明确报错 |
| `\Q...\E` | 支持 | 支持（编译前自动改写） |
| `\h`、`\R` | 支持 | 支持（自动展开为等价字符类） |
| `\X`（字形簇） | 支持 | 不支持，明确报错 |
| `\b` 宽度 | ASCII 语义 | 全字匹配按 ASCII 判定 |
| 灾难性回溯 | 可能卡住界面 | 超过回溯上限直接报错，不会卡死 |
| 非 UTF-8 / 二进制文件 | 按字节搜索 | 自动识别 UTF-8 / UTF-16 / GBK；二进制跳过 |

## 实现

```
Webview（侧边栏面板）
      │ postMessage
TypeScript 扩展宿主（命令、文件遍历、装饰器、替换）
      │ WebAssembly 调用
Rust 内核（fancy-regex：编译、匹配、替换展开、偏移映射）
```

- 内核编译目标 `wasm32-unknown-unknown`，通过手写 C ABI 与宿主通信，不使用 wasm-bindgen。
- 匹配结果以 UTF-8 字节偏移返回，宿主编译单次线性扫描映射为 UTF-16 偏移。
- 跨文件搜索支持取消与进度；超过 2 MB 的文件走 `src/search/stream.ts` 的分块通道，按 4 MB 读取、256 KB 重叠，编码用流式解码器增量处理。

## 开发

```bash
npm install
npm run build        # 编译 Rust 内核 + 打包扩展
npm test             # 内核、偏移映射、过滤器、流式分块、多文件、真实目录（含 10 MB 日志）、面板与冒烟测试（99 个用例）
npm run package      # 产出 .vsix
```

需要 Rust 工具链与 `wasm32-unknown-unknown` 目标：

```bash
rustup target add wasm32-unknown-unknown
```

## 已知限制

- VS Code 不支持真正悬浮的窗口，面板固定在侧边栏（可拖到次级侧边栏）。
- 正则回溯超限会报错而不是无限等待，这是刻意的取舍。
- 流式搜索中，单个匹配本身超过 256 KB 且跨过分块边界时可能漏报（普通文本与日志不受影响）。
- 在文件中替换只作用于能被 VS Code 以文本打开的编码；替换后不会自动保存。
